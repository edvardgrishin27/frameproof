# frameproof

**Ваш агент не смотрел это видео. Он угадал.**

Попросите Claude Code «посмотри туториал» — и он нарежет кадры по порогу смены сцен.
На скринкасте этот порог сработать не может. Инструмент может предупредить, что кадров
мало, но не скажет, ГДЕ именно дыра — а значит агент не отличит «кадров немного» от
«кадров нет двадцать минут подряд».

Замер на реальном 38-минутном гайде: самый популярный инструмент ниши **по умолчанию**
извлёк 17 кадров с дырой в **20 минут 51 секунду**. `frameproof` — 220 кадров с
максимальным разрывом **14 секунд**, первой командой, без флагов.

Полная таблица, включая их лучший режим, где они по покрытию впереди —
в [bench/RESULTS.md](bench/RESULTS.md). Прятать это неинтересно.

```bash
pip install frameproof
frameproof index "https://youtube.com/watch?v=..." --ocr
```

## Почему порог не может работать

Фильтр `scene` в ffmpeg считает **среднюю** дельту по всему кадру. Замерено на
ffmpeg 8.0.1 на реальных цветах терминала (`#cccccc` на `#1e1e1e`, кадр 640×360):

| что изменилось на экране | scene score | порог 0.3 |
|---|---|---|
| одна строка текста во всю ширину | 0.0579 | не сработал |
| три строки | 0.149 | не сработал |
| полэкрана | 0.745 | сработал |

Реальные глифы покрывают 10–15 % площади строки, поэтому набранная команда даёт скор
порядка **0.006 — промах примерно в 40 раз**. Понижение порога не спасает: то, что
вытянет скринкаст, взорвёт динамичное видео тысячами кадров.

`frameproof` считает **долю изменившихся пикселей по ячейкам сетки**, и сравнивает её
с собственным фоном каждой ячейки. Область, которая шевелится постоянно — камера с
ведущим, бегущий таймер, курсор — глушится сама собой. Ячейка, которая молчит большую
часть ролика и вдруг изменилась, — это событие.

Различает эти два случая медиана, а не амплитуда: слайд и терминал меняются вспышками
на фоне долгой неподвижности, а камера — непрерывно.

## Гарантия

**Ни один участок таймлайна не остаётся без кадра дольше `--max-gap` секунд**
(по умолчанию 15). Молчат детекторы — кадры ставятся по сетке. Покрытие перестаёт быть
вопросом удачно подобранного порога.

А когда гарантию выдержать нельзя, инструмент **говорит об этом**:

```
покрытие: 97 % — 2 участка без кадров (57 с). НЕ утверждай, что показано на экране в них.
    БЕЗ КАДРА  25:30 – 25:59   (29 с)
```

Молчаливая слепота хуже честного «здесь я не смотрел».

## Три команды — и это не вкусовщина

| команда | что делает | картинки |
|---|---|---|
| `index` | строит индекс, печатает покрытие | нет |
| `search` | ищет по речи **и по тексту с экрана** | нет |
| `frames` | отдаёт изображения | да, единственная |

Если бы поиск мог вернуть картинки, экономия исчезала бы на первом же запросе. Кадр
1280×720 стоит около 1196 визуальных токенов, а транскрипт часа — примерно 50 КБ.
Большинство вопросов закрывается вообще без изображений.

```bash
frameproof search "openrouter" --out ~/.frameproof/hermes
# [9:57 / f0050] screen: ... OpenRouter • дешевле напрямую ...

frameproof frames --at 18:38 --out ~/.frameproof/hermes
# [18:38 / f0097] .../frames/f0097.jpg  (1196 токенов)
```

Поиск подстрочный, по триграммам: `памят` находит и «память», и «памяти».
Запросы короче трёх символов (`AI`, `v2`) триграммам не по зубам — для них
включается прямой проход по строкам.

## Метка, которую можно проверить

`[18:38 / f0097]` — не оформление. Это ссылка на строку индекса, и её проверяет арифметика:

```bash
frameproof verify разбор.md --out ~/.frameproof/hermes
```

```
✗ [20:00 / f9999] На экране показана итоговая схема памяти агента.
      FAIL  FRAME_NOT_FOUND: кадра f9999 в индексе нет — ссылка выдумана
✗ [5:00 / f0097] Тут он открывает настройки роутера.
      FAIL  TIME_MISMATCH: метка говорит 5:00, а кадр f0097 снят в 18:38
?  [29:31 / f0160] Показан список из десяти навыков.
      WARN  NEVER_OPENED: кадр существует, но ни разу не запрашивался —
            утверждение сделано, не посмотрев
```

Шесть проверок, ни одного обращения к модели: существует ли кадр · совпадает ли тайм-код ·
не попал ли момент в участок без кадров · **выдавался ли кадр агенту вообще** ·
есть ли процитированная строка в тексте кадра · есть ли она в речи рядом.

## Слепой второй взгляд

Смысл механика проверить не может. Для этого — отдельный субагент, который видит
**только кадр и утверждение**: ни вопроса пользователя, ни рассуждений автора, ни
остального разбора. Его задача — попытаться опровергнуть.

```bash
frameproof verify разбор.md --out <индекс> --plan   # задания без единого слова контекста
```

Запускается **только по явной просьбе**. Опровергнутое **помечается, а не скрывается**:
на замерах состязательные панели дают до трети ложных срабатываний, поэтому решение
остаётся за человеком.


## Установка

```bash
pip install frameproof          # ядро
pip install "frameproof[net]"   # + yt-dlp для ссылок
pip install "frameproof[mlx]"   # + быстрая локальная расшифровка на Apple Silicon

frameproof doctor               # что есть, чего нет
frameproof install              # поставить скилл в Claude Code
```

Нужен `ffmpeg`. Остальное необязательно и деградирует мягко.
**Ключи не нужны нигде.** Субтитры yt-dlp берёт бесплатно; если их нет — расшифровка
идёт локально.

## В Claude Code

После `frameproof install` достаточно попросить: *«посмотри это видео и скажи, какую
команду он показывает на 4:12»*. Скилл держит одно правило, которое агент не может обойти:

> Никогда не утверждай, что было на экране, не увидев кадра. Каждое утверждение про
> экран — с меткой `[MM:SS / fNNNN]`, чтобы человек мог проверить.

## Честные границы

Полный список — в [CLAIMS.md](CLAIMS.md). Коротко: инструмент гарантирует *покрытие*,
а не то, что не пропущено ни одно изменение; OCR нужен, чтобы **найти** кадр, а не
читать код дословно; замер — один ролик того класса, где разрыв максимален.
