# Что этот инструмент делает, а что нет

Документ существует, чтобы никто — включая автора — не приписал `frameproof` того,
чего он не умеет. Каждое утверждение ниже либо проверяемо командой, либо помечено
как непроверенное.

## Что заявлено и как это проверить

| Заявление | Как проверить |
|---|---|
| Работает офлайн, без API-ключей | Отключите сеть после `index` — `search` и `frames` работают. Для локального файла сеть не нужна вообще |
| Гарантирует, что без кадра не остаётся участок длиннее `--max-gap` | `frameproof report --out <индекс>` → строка «покрытие» |
| Честно сообщает, если гарантию выдержать не удалось | `pytest -k потолок` — тест на это есть |
| Ловит переходы там, где порог сцен слепнет | `pytest -k скринкаст` |
| Не путает вечно шевелящуюся камеру с переходом | `pytest -k голова` |
| Формула токенов совпадает с документацией Anthropic | `pytest -k токен` — 6 контрольных значений из официальной таблицы |
| Замер против `claude-video` воспроизводится | `python3 bench/benchmark.py --video <файл>` |

## Замер против claude-video

Проведён на ролике «HERMES AGENT 3.0», 38:32, 1080p. Запускался **настоящий код**
`bradautomates/claude-video` (не пересказ алгоритма), режим по умолчанию `balanced`,
оба инструмента получили один и тот же локальный файл.

| | claude-video | frameproof |
|---|---|---|
| кадров | 17 | 191 |
| максимальный разрыв | 20 мин 51 с | 14 с |
| в зонах >30 с без кадра | 2263 с (98 %) | 0 с (0 %) |
| время работы | 55 с | 41 с |

Их движок сообщил о себе сам: `engine=scene, fallback=False, candidates=17`.

### Что здесь честно уточнить

- **Их фолбэк на равномерную нарезку существует и работает** — просто не сработал.
  Порог входа `SCENE_MIN_FRAMES = 8`; ролик набрал 17 кадров на монтажных склейках
  интро и аутро, порог прошёл, и фолбэк не включился. На видео совсем без склеек
  их инструмент ушёл бы в равномерную нарезку и результат был бы другим.
- **Режим не при чём.** Со снятым потолком (`token-burner`) — те же 17 кадров.
  Узкое место в детекторе, а не в бюджете.
- **Это один ролик.** Скринкаст-гайд с говорящей головой — тот класс видео, где
  разрыв максимален. На смонтированном ролике с частыми склейками разница будет меньше.
- **Мы НЕ утверждаем, что claude-video сломан.** Распространённое мнение, будто он
  не работает из-за удаления флага `-vsync` из ffmpeg, проверено запуском: в ffmpeg
  8.0.1 флаг объявлен устаревшим, но работает.
- **Про ключи корректная формулировка такая:** без ключа `claude-video` расшифрует
  только то, у чего уже есть готовые субтитры (их берёт `yt-dlp` бесплатно). Своё
  видео, Loom, запись Zoom останутся без транскрипта. `frameproof` расшифровывает
  локально в любом случае.

## Чего инструмент НЕ делает

- **Не гарантирует, что не пропущено ни одно изменение экрана.** Гарантия другая и
  проверяемая: между соседними кадрами не больше `--max-gap` секунд. Изменение,
  случившееся и отменившееся внутри этого промежутка, будет пропущено.
- **Не читает текст с экрана дословно.** OCR путает пунктуацию (`[main` → `Imain`),
  а в коде пунктуация несёт смысл. OCR нужен, чтобы НАЙТИ нужный кадр; что на нём
  написано — читает модель глазами.
- **Не измеряет качество разбора.** Меряется покрытие и число кадров — то, что можно
  проверить. «Насколько лучше агент понял видео» инструментом не измеряется.
- **Не работает с приватным видео за логином.** Обход авторизации не делается.
- **Не заменяет просмотр человеком** там, где важна интонация, монтажный ритм или
  происходящее между выбранными кадрами.

## Непроверенное

- **`parakeet-mlx`** как более быстрый движок расшифровки для русского выглядит
  перспективно, но нами не замерялся. В каскаде его нет.
- **Работа в Codex CLI.** Формат `SKILL.md` переносим, но мы этого не проверяли и
  поддержку не заявляем. Нужна — напишите в issues.
- **Windows и Linux.** Ядро на ffmpeg и numpy кроссплатформенно, но обкатано только
  на macOS (Apple Silicon). OCR через Apple Vision — только macOS, без него
  инструмент работает, просто экран не грепается.
