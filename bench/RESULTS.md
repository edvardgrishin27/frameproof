# Замер: frameproof против claude-video

## Условия

- Ролик: «HERMES AGENT 3.0: полный гайд июль 2026», 38:32, 1080p, av1
- Один и тот же локальный файл обоим инструментам — никто не качает своё
- `claude-video` запущен **своим кодом** (`extract_scene_or_uniform`), режим по
  умолчанию `balanced` (`auto_fps` → fps 0.0433, потолок 100)
- Дата: 30.07.2026, ffmpeg 8.0.1, macOS Apple Silicon

Воспроизвести:

```bash
python3 bench/benchmark.py --url "https://www.youtube.com/watch?v=7IJtqSEwra0"
```

## Результат

| | claude-video | frameproof |
|---|---|---|
| кадров | 17 | 191 |
| максимальный разрыв | **20:51** | **14 с** |
| в зонах >30 с без кадра | 2263 с (98 %) | 0 с (0 %) |
| время работы | 55 с | 41 с |

`claude-video` сообщил о себе сам: `engine=scene, fallback=False, candidates=17`.
Крупнейшая дыра — с 2:37 до 23:29.

`frameproof`: 64 пойманных перехода + 127 кадров страховки покрытия, покрытие полное.

## Что здесь важно понять правильно

**Фолбэк у claude-video есть и работает — просто не сработал.** Порог входа
`SCENE_MIN_FRAMES = 8`. Ролик набрал 17 кадров на монтажных склейках интро и аутро,
порог прошёл, и переключение на равномерную нарезку не включилось. Дальше 33 минуты
гайда получили 4 кадра.

Это тоньше, чем «инструмент плохой»: у видео со смонтированным интро детектор проходит
проверку живости и после этого слепнет в теле ролика — там, где как раз показывают экран.

**Режим не при чём.** Со снятым потолком кадров (`token-burner`, `max_frames=None`) —
те же 17 кадров. Узкое место в детекторе, а не в бюджете.

**Это один ролик.** Скринкаст-гайд с говорящей головой — класс видео, где разрыв
максимален. На смонтированном ролике с частыми склейками разница будет меньше.

**Мы не утверждаем, что claude-video сломан.** Ходовое мнение, будто он не работает
из-за удаления флага `-vsync` из ffmpeg, проверено запуском: в ffmpeg 8.0.1 флаг
объявлен устаревшим, но работает.
